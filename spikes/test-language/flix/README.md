# Flix startup probe

This optional probe uses the user-requested [flixw](https://github.com/wstein/flixw)
wrapper, release 0.34.9, pinned to unmodified Flix 0.79.0. Wrapper guidance was
read at `5b627a3c858c80ef351d1f119bf08040dce7d048`. The setup asset SHA-256 from
that revision's README is
`8db484443e822d200a59bbce1d9a64bb6a679c1446a61724cca0ba51732b77d6`.
The committed wrapper lock pins the compiler to
`8fad2aa09567a7edabcc43f4101fa6199131df2c22929e001c87659d764f6dcf`.
The wrapper is third-party experimental MIT software, not an official Flix tool;
its retained license is [WRAPPER-LICENSE.txt](WRAPPER-LICENSE.txt). The compiler is
[Apache-2.0](https://github.com/flix/flix/blob/v0.79.0/LICENSE.md). No binaries or
new production dependencies are committed.

## Coverage

The unchanged Python replayer generates typed fixtures from all 100 real counter
witnesses. Flix independently rotates each of the 24 complete physical sticker
frames, compares the entire reached state with the Python expectation and checks
the complete inverse. Six negative controls exercise a wrong print-up frame,
missing expected state and four invalid move parameters. Negative quarter turns
and fourth powers are also checked.

Both `flixw test` and the compiled executable call exactly `geometryChecks()`.
The test runner reports one test because the full finite dataset is batched inside
that test. The optimized path does not remove checks.

This is **not a complete JSON certificate validator**: Python decodes witness JSON
and move notation into typed fixtures. The Flix prototype therefore cannot replace
the authoritative Python verifier or inherit its schema/corruption coverage.
Typed fixture generation originally exceeded the JVM 64-KB method limit; splitting
it into 100 functions retained all data and allowed compilation. Large raw witness
parsing, production certificate formats and general migration equivalence remain
UNKNOWN.

## Reproduce

Use Java 21 and temporary caches. Setup is needed only once; later wrapper commands
verify the locked compiler bytes. The wrapper setup may download its own launcher
into the configured temporary cache, never the user's system PATH.

```sh
curl -fsSL https://github.com/wstein/flixw/releases/download/v0.34.9/flixw-setup.java -o /tmp/flixw-setup.java
echo '8db484443e822d200a59bbce1d9a64bb6a679c1446a61724cca0ba51732b77d6  /tmp/flixw-setup.java' | sha256sum -c -
export FLIX_CACHE_HOME=/tmp/cubistry-flix-cache
export COURSIER_CACHE=/tmp/cubistry-flix-coursier
java /tmp/flixw-setup.java --pin 0.79.0
python3 generate_fixture.py
./flixw test --no-install --threads 2
./flixw build-fatjar --no-install --threads 2
java -jar artifact/flix.jar
python3 measure.py --output /tmp/NEW-flix-results --setup /tmp/flixw-setup.java
```

Run from this directory. Managed proxy environments may additionally require
standard Java `http.proxyHost`, `http.proxyPort`, `https.proxyHost` and
`https.proxyPort` properties in `JAVA_TOOL_OPTIONS`, inherited by the wrapper's
child JVM. This experiment used proxy host `proxy`, port `8080`, with TLS
verification enabled. `COURSIER_CACHE` avoids Flix's default read-only home cache.

The measurement compares three cached-compiler test invocations against three
fresh JVM invocations of the built fat JAR. It also records an empty-wrapper-cache
setup and the separate compilation cost. The compiled artifact must be rebuilt
when sources change. Timing on this shared machine is observational, not a universal
performance promise; source hashes and all raw stdout/stderr are retained.

An automatic approval review rejected recursive removal of Flix init's unused
nested `.github` scaffolding. No deletion was performed. Those autogenerated files
remain untracked in the author worktree and are excluded from the explicit commit
file list; the repository's workflows are unchanged.

## Observed result

At source `8094804`, the final three cached-wrapper compiler/test invocations had
a median **9,304 ms**; three fresh compiled-JVM executions had a median **177 ms**.
Both ran the identical 100-state, 100-inverse, six-negative-control function.
This is approximately 52× lower invocation latency after compilation, not a
language-wide speedup. The separate build and empty-cache setup costs remain in
[the raw report](evidence/report.json). The compiler download was 37.5 MiB; the
produced executable fat JAR was about 682 KiB. Existing Python tests were neither
removed nor modified.

## One-process lifecycle instrumentation

`src/Lifecycle.flix` provides a separate `lifecycleMain` entry point. It emits and
flushes `CUBISTRY_PHASE` JSON markers for READY, four RESULT records and DONE.
Every invocation calls the original `geometryChecks()` unchanged, including all
100 canonical full-frame comparisons, 100 inverse checks and six negative
controls. All checker data is immutable; each call has its own locally constructed
source/reached lists, with no mutable validator state shared across calls.

Each invocation additionally replays the 100 words to compute a numeric checksum
over all reached IDs, cubies, positions, normals, up vectors and image lengths.
That extra audit is inside every invocation's timer. It is explicitly additional
work relative to the original startup probe, so lifecycle timings are not compared
as identical-work measurements with the earlier startup table. The checksum audit
is not a replacement for the complete frame/image equality assertions.

Compile first, separately, then observe one fresh JVM process:

```sh
python3 build_lifecycle.py --output /tmp/NEW-flix-build.json
python3 ../lifecycle_driver.py --output /tmp/NEW-flix-lifecycle --label flix -- java -jar artifact/flix-lifecycle.jar
python3 verify_lifecycle.py /tmp/NEW-flix-lifecycle/report.json
```

The common Python observer uses its own monotonic clock for process-start → READY
and flushed DONE receipt → `Popen.wait()` completion. Child validation durations
use `System.nanoTime()` only within the JVM; no timestamps from different clocks
are subtracted. The first validation and three later full validations are all
retained. JVM/JIT/class caches may affect later calls; no forced collection,
assertion disabling or forced-zero exit tail is used. Class loading before READY
is included in observed startup, while any first-use loading inside validation
remains in that invocation. The build cost is outside all runtime phases.

The lifecycle build retains a separate `artifact/flix-lifecycle.jar`, so rebuilding
the original startup probe cannot silently replace the lifecycle executable.

The retained [lifecycle capture](evidence/lifecycle/report.json) observes startup
**38.47 ms**, first complete invocation **134.08 ms**, and three later complete
invocations **19.02 / 9.85 / 13.65 ms** in the same JVM. Every invocation reported
checksum **29748**, independently checked against the unchanged Python geometry.
The measured DONE-to-exit tail was **7.10 ms**, not zero. Whole-process observed
wall time was **259.65 ms**; marker construction, flushing, pipe delivery and
scheduling are included outside the child validation timers. The separately
recorded [upfront build](evidence/lifecycle/build.json) took **8,907.17 ms**.
These are one shared-machine observation; earlier exploratory repeats are not
silently averaged into it. No standalone certificate-load time is claimed.
