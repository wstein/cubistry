# One application instead of single-page entry points

## Purpose
Complete one application under `index.html`: all public functions of the legacy root HTML pages use the shared navigation, controls, design and lifecycle. Old product URLs are removed without redirects. This plan combines the original owner decisions with the full source audit and completion amendment of 2026-11-10. The front matter stays `draft` because [CONVENTIONS](../CONVENTIONS.md) defines no owner-approved plan status; the plan itself does not confer implementation or publication approval beyond recorded owner instructions.

## Seamless completion amendment (owner, 2026-11-10)

This is the current completion plan. The owner requested a review of all root HTML pages against the [deployed landing page](https://wstein.github.io/cubistry/index.html), then clarified "make fully integrate seamless" and "drop old urls". These instructions authorize the complete product migration and intentional removal of the old URLs. This documentation PR makes that scope reviewable; it does not implement ports or delete pages.

The following changes explicitly replace earlier decisions in this document:

- Decisions 2, 7, 8, 13, 14 and 17 continue: one `index.html` host, `?app=<id>`, no redirects or aliases, no last-app autostart, a light landing hero, and Apps/Cubes on the landing page.
- Decision 9 no longer keeps `licenses.html`; its complete notices become an integrated utility view. Decision 10 no longer keeps `print.html` or opens a separate product document; its existing preset viewer and downloads become an integrated utility view, still reached from slot 5 with the actual physical design. Neither utility joins the Apps/Cubes chooser.
- The open decision about `solver-acceptance.html` and `library-example.html` is resolved for product scope: remove both root URLs and production inputs. Preserve their independent acceptance/library consumers under explicit development/test fixture paths, without an app tile. Do not rehost a legacy product under an internal-looking name.
- The stage estimates, current-state section, slot statuses and URL appendix dated November 7–8 below are historical evidence, not the current backlog or a claim of parity. The audit and gates in this amendment replace their remaining execution order and exceptions. ADR-0001's accepted tokens and font obligations remain unchanged; no accepted ADR authorizes keeping these URLs.

### Host, route and state contract

Keep the existing registry/router and extend their contracts; do not introduce another app registry, hash router, document navigation or iframe wrapper. The proposed utility key `view=print|licenses` is a small extension of `resolveHostView` and `createRouter`, not another product entry point. It needs plan review before implementation. A utility may retain `app` as its return context: `index.html?app=calendar&view=print&design=de-a`. With no `app`, closing a utility returns to landing. `view` takes display precedence while the app context is suspended. Unknown app IDs retain the existing landing behavior; unknown utility values resolve to the app/landing rather than a blank shell. Utilities are absent from `AppGroup` and the app chooser. Internal fixtures never join either.

A single typed route parser/serializer owns app, optional utility and per-mode setup. Mode IDs stay those already accepted, with `calendar`, `playground` and `ci` joining only when functional. Proposed `cube=2|3` selects Playground's engine; there is no canonical `picture3` ID. Normalize only at the new host: the removed filenames, `application=` as an application selector and hash-style app aliases are not retained. Existing value aliases within an application's parameters can continue to parse on its new URL, with a canonical serialization; no old URL is redirected. Existing documentation's old URL examples must be rewritten as new host examples.

### Module and shell integration boundary

Extract mountable adapters beside each existing engine under `src/apps/<app>/`; retain domain controllers, certified data and factories. Entry scripts currently use `document.getElementById`, global listeners, global exports, intervals and top-level async work; importing them into the host is not a mount. Replace document queries with mount-owned roots, pass deployment base and route explicitly, bind controls through `ModeShell`, and return deterministic cleanup. Keep pure model/controller code independent of DOM and shell.

Extend the existing mount contract only for a demonstrated common need: route updates and utility suspend/resume are the expected additions. Every async font/asset/worker/storage step checks mount generation after `await`. Cleanup owns listeners, observers, animation frames, intervals, demo delays, controller drivers, worker requests, WebGL resources, image URLs and database connections. Cancellation respects each engine's current-turn completion contract; cleanup must not fabricate a physical completion. Move `ensureProof()` into the consumers that require that proof and lazy-import heavy engines inside mode mounts, so opening Calendar or Licenses does not first require the Counter certificate or picture solver. Preserve all module-relative worker/subworker/WASM/bin loading, validated base paths, request IDs and cancellation semantics; no copied worker or new solver fallback.

Use the accepted five dock slots, primary action, status/error rows, per-cube readouts, reference view, Nerd drawer, Appearance and one Present control. Long forms such as picture crops, fit analysis, local library, print previews and legal text use scrollable integrated content regions with accessible headings; they are not forced into tiny cube readouts or hidden inside the diagnostic drawer. The phone sheet/switcher still has a known implementation gap; design fidelity must be reviewed alongside functionality. Keep ADR-0001 contrast/font requirements. Preserve physical sticker fonts separately from UI fonts, and retain every OFL notice when a font choice becomes shared.

No legacy HUD, chooser, duplicated footer, body-level presentation handler or stylesheet that changes unrelated modes may remain mounted. Products show user terms, not module/router/generation jargon. No new print-sheet generator, artwork regeneration, physical-layout change, provider migration, authentication, workflow start or publication is part of this migration.

## Dock slot API
Status: built in the stack #324 (API, markup, styles, tests) and #325 (reference mode); `UNKNOWN` in a browser until the Playwright lane has run on them. Source: `src/apps/shell/slot-api.ts`; the region names and the slot map are those of the [design proposal](../../docs/design/README.md).

A mode receives a `ModeShell` in its mount context (`MountContext.shell`) and uses it instead of touching the regions of `index.html`:
- `setSlot(n, { label, element | render })`, `clearSlot(n)`, `clearSlots()`: slots 1 Action, 2 Value, 3 Mode, 4 Motion, 5 Print & appearance. A filled slot is a `role="group"` labeled by an `h2`; an empty slot keeps `hidden`. DOM order is tab order.
- `setPrimaryAction({ label, onClick, disabled? })`: the one berry button.
- `setStatus(state, text?)`: one chip in the existing `role="status"` zone, states `ready, moving, sync, paused, done, warn, error` (tokens `--s-*`). The same state and text writes nothing; callers set it on state transitions, never per frame. The readout (`setReadout`, `updateReadout`) is plain text without a live region.
- `setWarning({ title, text, onDismiss? })`, `setError({ text, onDismiss? })` (`null` clears): one dismissible `role="alert"` row per kind beside the status zone, outside its polite live region; unchanged rows are not reinserted when the chip changes.
- `setNerd({ title, render })`, `refreshNerd()`: the drawer is hidden until the Nerd button (`#nerd-toggle`, in the header between Appearance and Presentation) is pressed or the URL has `nerd=1`; `render` runs only while it is open, and a refresh keeps the focused control and the scroll position. `nerdTable` and `nerdFacts` build the content.
- `setHint(text | null)`, `setReferenceView(handler | null)`, `listen(...)`, `onDispose(fn)`.

Cleanup: the router creates the shell per mount and disposes it with the mode. Every write checks `isCurrent()`, so a mode that is superseded during an async init cannot put content into the next mode.

### What `print.html` is
Facts read from the repository at `eb1dcce3`; the run-time behavior is `UNKNOWN` here.
- Title "Cubistry · Print stickers" (`print.html:11`); script `src/print.mjs` (94 lines).
- It generates vector print and cut sheets with rounded sticker cuts and an assembly guide (`docs/PRINT_STICKERS.md`: `print.pdf`, `artwork-N.svg`, `cuts-N.svg`, `assembly.pdf`, `manifest.json`).
